Binary Search

Halve the search space every step and a million items take only 20 comparisons. The idea is simple, but off-by-one errors make it notoriously easy to get wrong. This page gives you one way of thinking — a monotonic yes/no condition plus a loop invariant — that works for every variant.

01 The basics

What is binary search?

Binary search finds a target in a sorted range by looking at the middle element and throwing away the half that can’t contain the answer.

  • Look at mid. Too small? The answer is to the right. Too big? To the left.
  • Each step halves the range → O(log n) time, O(1) space.
  • Linear search on 1,000,000 items: up to 1,000,000 checks. Binary search: at most 20.

Doubling the input adds just one step.

The real requirement: a monotonic condition

“Sorted array” is just the most common case. Binary search works whenever you can ask a yes/no question whose answers look like this across the range:

All nos, then all yeses. Binary search finds the boundary — the first yes. Every variant (lower bound, first bad version, minimum speed, square root…) is “find the first yes” for a different question.

Examples of the yes/no question

  • Sorted array, target t: a[i] >= t?
  • First bad version: isBad(v)?
  • Integer square root of x: m * m > x?
  • Koko’s bananas: can she finish at speed k?
  • Rotated array: a[i] <= a[last]? (finds the minimum)
Computing mid safely: (lo + hi) / 2 can overflow when lo + hi exceeds the int range (a real bug that sat in Java’s standard library for years). Use lo + (hi - lo) / 2. Python integers don’t overflow, so (lo + hi) // 2 is fine there.

02 Templates you should know by heart

Learn these three. Write each one with its invariant in a comment until you no longer need to.

1 · Exact match (lo <= hi)

Search space is the closed range [lo, hi]. Stop as soon as you find it; return −1 if the range becomes empty.

int binarySearch(vector<int>& a, int target) {
    int lo = 0, hi = a.size() - 1;      // search [lo, hi]
    while (lo <= hi) {                  // range not empty
        int mid = lo + (hi - lo) / 2;
        if (a[mid] == target) return mid;
        if (a[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;
}
int binarySearch(int[] a, int target) {
    int lo = 0, hi = a.length - 1;      // search [lo, hi]
    while (lo <= hi) {                  // range not empty
        int mid = lo + (hi - lo) / 2;
        if (a[mid] == target) return mid;
        if (a[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;
}
def binary_search(a, target):
    lo, hi = 0, len(a) - 1              # search [lo, hi]
    while lo <= hi:                     # range not empty
        mid = (lo + hi) // 2
        if a[mid] == target:
            return mid
        if a[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1

2 · Lower bound — first index with a[i] >= t

Half-open range [lo, hi) with hi = n. The answer may be n (“not found / insert at end”). Loop ends when lo == hi, which is the answer.

int lowerBound(vector<int>& a, int t) {
    int lo = 0, hi = a.size();          // answer in [lo, hi]
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] >= t) hi = mid;      // mid could be the answer
        else lo = mid + 1;              // mid is definitely not
    }
    return lo;                          // == hi
}
int lowerBound(int[] a, int t) {
    int lo = 0, hi = a.length;          // answer in [lo, hi]
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] >= t) hi = mid;      // mid could be the answer
        else lo = mid + 1;              // mid is definitely not
    }
    return lo;                          // == hi
}
def lower_bound(a, t):
    lo, hi = 0, len(a)                  # answer in [lo, hi]
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] >= t:
            hi = mid                    # mid could be the answer
        else:
            lo = mid + 1                # mid is definitely not
    return lo                           # == hi

Upper bound (first a[i] > t) is the same with >. Count of t = upper − lower. Last index of t = upper − 1.

3 · Generic “first true” on a predicate

The master template. Plug in any monotonic ok(x) (false…false, true…true) over integers [lo, hi]. Make sure hi is a value where ok is surely true.

// smallest x in [lo, hi] with ok(x) == true
long long firstTrue(long long lo, long long hi, function<bool(long long)> ok) {
    while (lo < hi) {
        long long mid = lo + (hi - lo) / 2;
        if (ok(mid)) hi = mid;
        else lo = mid + 1;
    }
    return lo;
}
// smallest x in [lo, hi] with ok(x) == true
long firstTrue(long lo, long hi, LongPredicate ok) {
    while (lo < hi) {
        long mid = lo + (hi - lo) / 2;
        if (ok.test(mid)) hi = mid;
        else lo = mid + 1;
    }
    return lo;
}
# smallest x in [lo, hi] with ok(x) == True
def first_true(lo, hi, ok):
    while lo < hi:
        mid = (lo + hi) // 2
        if ok(mid):
            hi = mid
        else:
            lo = mid + 1
    return lo

“Last true” without an infinite loop

To find the largest x with ok(x) (true…true, false…false) you move lo = mid. Then mid must round up, or lo = 4, hi = 5 loops forever.

while (lo < hi) {
    long long mid = lo + (hi - lo + 1) / 2;   // round UP
    if (ok(mid)) lo = mid;
    else hi = mid - 1;
}
return lo;
while (lo < hi) {
    long mid = lo + (hi - lo + 1) / 2;        // round UP
    if (ok.test(mid)) lo = mid;
    else hi = mid - 1;
}
return lo;
while lo < hi:
    mid = (lo + hi + 1) // 2                  # round UP
    if ok(mid):
        lo = mid
    else:
        hi = mid - 1
return lo

Rule: if a branch does lo = mid, round mid up. If it does hi = mid, round down.

Built-in helpers

#include <algorithm>
auto it  = lower_bound(a.begin(), a.end(), t);   // first >= t
auto it2 = upper_bound(a.begin(), a.end(), t);   // first > t
bool has = binary_search(a.begin(), a.end(), t);
int idx  = it - a.begin();
int cnt  = it2 - it;                             // occurrences of t
import java.util.Arrays;
int i = Arrays.binarySearch(a, t);
// i >= 0  → found at i (any occurrence if duplicates!)
// i < 0   → not found, insertion point = -(i + 1)
// Collections.binarySearch(list, t) works the same for lists.
// TreeSet / TreeMap: ceiling(t) = smallest >= t, floor(t) = largest <= t
from bisect import bisect_left, bisect_right, insort
i = bisect_left(a, t)     # first index with a[i] >= t  (lower bound)
j = bisect_right(a, t)    # first index with a[j] > t   (upper bound)
count = j - i             # occurrences of t
insort(a, t)              # insert keeping a sorted
# Python 3.10+: bisect_left(a, t, key=func)

    04 Binary search on the answer

    The most important idea for interviews. When a question asks for the minimum X that works (or maximum), and checking “does X work?” is easy, binary search over X.

    Recognise it

    • “Minimise the maximum …” / “maximise the minimum …”
    • “Smallest speed / capacity / days / size such that …”
    • If X works then X+1 also works (or the reverse) → monotonic.
    • Writing feasible(X) is an O(n) greedy pass.

    Recipe

    1. Define the answer range [lo, hi] — smallest and largest possible answers.
    2. Write feasible(x) — usually a greedy simulation.
    3. Check monotonicity in your head.
    4. Run “first true” (min answer) or “last true” (max answer).
    5. Total time: O(n · log(range)).

    Worked example — Koko eating bananas

    Piles [3, 6, 7, 11], h = 8 hours. Each hour Koko eats up to k bananas from one pile. Find the minimum k to finish in time. Hours needed at speed k = Σ ⌈pile / k⌉.

    Answers form false…false, true…true. Binary search finds the first true: k = 4.

    05 Tips & tricks to learn it properly

    🎯

    Think “first true”

    Turn every problem into a monotonic yes/no question and find the boundary. One mental model instead of ten templates.

    📜

    Write the invariant

    e.g. “answer is always in [lo, hi]”. Each update must keep it true; then the return value is obvious.

    🔒

    Pick one range style

    Closed [lo, hi] pairs with lo <= hi and hi = mid − 1. Half-open pairs with lo < hi and hi = mid. Don’t mix.

    ♾️

    Avoid infinite loops

    Every iteration must shrink the range. If you write lo = mid, round mid up: lo + (hi − lo + 1) / 2.

    💥

    Overflow-safe mid

    lo + (hi − lo) / 2. And use long when the answer range or mid * mid can exceed 2³¹.

    🧪

    Test tiny inputs

    Arrays of size 0, 1, 2; target smaller than all, larger than all, and duplicated. Most bugs show up with 2 elements.

    🔄

    Rotated arrays

    At least one half around mid is always sorted. Find which half, check if the target is inside it, discard the other.

    ⛰️

    Compare with a neighbour

    No target? Compare a[mid] with a[mid+1] (peaks) or with a[hi] (rotation minimum).

    📐

    Answer space, not index space

    You can binary search over values: speeds, days, distances, √x. The array doesn’t even need to exist.

    🔢

    Real numbers

    For doubles, loop a fixed ~100 times (or until hi − lo < 1e-9) instead of comparing for equality.

    📚

    Know your library

    lower_bound, bisect_left, TreeMap.ceilingKey save time and bugs in contests.

    🗣️

    Trace out loud

    In interviews, dry-run 2–3 iterations on the example writing lo / mid / hi. It catches off-by-ones instantly.

    Common mistakes checklist

    • Applying binary search to unsorted / non-monotonic data.
    • while (lo < hi) with hi = mid − 1 → skips the answer.
    • lo = mid with mid rounding down → infinite loop.
    • hi = n − 1 when the answer can be n (insert position).
    • Returning mid after the loop instead of lo.
    • mid * mid overflowing int in square-root problems.
    • Wrong answer-space bounds (e.g. lo = 0 when speed 0 divides by zero).

    A 10-day practice plan

    1. Day 1: classic search, search insert position — write both templates from memory.
    2. Day 2: first/last position, count occurrences, library functions.
    3. Day 3: sqrt(x), perfect square, first bad version (predicate thinking).
    4. Days 4–5: rotated arrays: search, minimum, with duplicates.
    5. Day 6: peak element, single element in sorted array (neighbour tricks).
    6. Days 7–8: on the answer: Koko, ship packages, bouquets, aggressive cows.
    7. Day 9: split array largest sum, 2D matrix search.
    8. Day 10: median of two sorted arrays; redo any you got wrong.
