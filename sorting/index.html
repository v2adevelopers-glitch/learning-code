Sorting

Putting things in order is the most common preprocessing step in all of programming — and the gateway to binary search, two pointers, greedy and more. Learn how the classic algorithms work, why O(n log n) is the limit for comparison sorts, and how to use your language’s built-in sort correctly.

01 The basics

Words you need to know

  • Stable: equal elements keep their original relative order. Matters when you sort by one key after another.
  • In-place: uses O(1) (or O(log n)) extra memory instead of a full copy.
  • Comparison sort: only learns about the data by asking “is a < b?”.
  • Adaptive: runs faster when the input is already nearly sorted (insertion sort, TimSort).

Why O(n log n) is the floor

There are n! possible orders of n items. Each comparison answers one yes/no question, so it can at best halve the possibilities. You need at least log₂(n!) ≈ n log₂ n comparisons to single out the right order.

Counting sort and radix sort beat this by not comparing — they use the values as array indices, which only works for small integer keys.

What real libraries use: hybrids. C++ std::sort is introsort (quick sort that switches to heap sort if recursion gets too deep, and insertion sort for tiny ranges). Java and JavaScript (V8) use TimSort for objects — merge sort + insertion sort that exploits already-sorted runs.

02 The classic algorithms

Bubble sort

Repeatedly swap adjacent out-of-order pairs; the largest value “bubbles” to the end each pass. Stop early if a pass makes no swaps.

void bubbleSort(vector<int>& a) {
    int n = a.size();
    for (int i = 0; i < n - 1; i++) {
        bool swapped = false;
        for (int j = 0; j < n - 1 - i; j++)
            if (a[j] > a[j + 1]) { swap(a[j], a[j + 1]); swapped = true; }
        if (!swapped) break;              // already sorted
    }
}
void bubbleSort(int[] a) {
    int n = a.length;
    for (int i = 0; i < n - 1; i++) {
        boolean swapped = false;
        for (int j = 0; j < n - 1 - i; j++)
            if (a[j] > a[j + 1]) {
                int t = a[j]; a[j] = a[j + 1]; a[j + 1] = t;
                swapped = true;
            }
        if (!swapped) break;              // already sorted
    }
}
function bubbleSort(a) {
    const n = a.length;
    for (let i = 0; i < n - 1; i++) {
        let swapped = false;
        for (let j = 0; j < n - 1 - i; j++)
            if (a[j] > a[j + 1]) { [a[j], a[j + 1]] = [a[j + 1], a[j]]; swapped = true; }
        if (!swapped) break;              // already sorted
    }
}

Selection sort

Find the minimum of the unsorted part and swap it to the front. Few swaps (≤ n), but always O(n²) comparisons — and not stable.

void selectionSort(vector<int>& a) {
    int n = a.size();
    for (int i = 0; i < n - 1; i++) {
        int m = i;
        for (int j = i + 1; j < n; j++)
            if (a[j] < a[m]) m = j;
        swap(a[i], a[m]);
    }
}
void selectionSort(int[] a) {
    int n = a.length;
    for (int i = 0; i < n - 1; i++) {
        int m = i;
        for (int j = i + 1; j < n; j++)
            if (a[j] < a[m]) m = j;
        int t = a[i]; a[i] = a[m]; a[m] = t;
    }
}
function selectionSort(a) {
    const n = a.length;
    for (let i = 0; i < n - 1; i++) {
        let m = i;
        for (let j = i + 1; j < n; j++)
            if (a[j] < a[m]) m = j;
        [a[i], a[m]] = [a[m], a[i]];
    }
}

Insertion sort

Like sorting playing cards in your hand: take the next card and shift bigger ones right until it fits. Very fast on small or nearly-sorted input.

void insertionSort(vector<int>& a) {
    for (int i = 1; i < a.size(); i++) {
        int key = a[i], j = i - 1;
        while (j >= 0 && a[j] > key) { a[j + 1] = a[j]; j--; }   // shift right
        a[j + 1] = key;
    }
}
void insertionSort(int[] a) {
    for (int i = 1; i < a.length; i++) {
        int key = a[i], j = i - 1;
        while (j >= 0 && a[j] > key) { a[j + 1] = a[j]; j--; }   // shift right
        a[j + 1] = key;
    }
}
function insertionSort(a) {
    for (let i = 1; i < a.length; i++) {
        const key = a[i];
        let j = i - 1;
        while (j >= 0 && a[j] > key) { a[j + 1] = a[j]; j--; }   // shift right
        a[j + 1] = key;
    }
}

Merge sort

Divide in half, sort each half recursively, merge the two sorted halves. Always O(n log n) and stable, at the cost of O(n) extra memory.

void mergeSort(vector<int>& a, int lo, int hi, vector<int>& tmp) {   // sorts [lo, hi)
    if (hi - lo < 2) return;
    int mid = (lo + hi) / 2;
    mergeSort(a, lo, mid, tmp);
    mergeSort(a, mid, hi, tmp);
    int i = lo, j = mid, k = lo;
    while (i < mid && j < hi) tmp[k++] = (a[i] <= a[j]) ? a[i++] : a[j++];  // <= keeps it stable
    while (i < mid) tmp[k++] = a[i++];
    while (j < hi) tmp[k++] = a[j++];
    for (k = lo; k < hi; k++) a[k] = tmp[k];
}
// call: vector<int> tmp(a.size()); mergeSort(a, 0, a.size(), tmp);
void mergeSort(int[] a, int lo, int hi, int[] tmp) {   // sorts [lo, hi)
    if (hi - lo < 2) return;
    int mid = (lo + hi) / 2;
    mergeSort(a, lo, mid, tmp);
    mergeSort(a, mid, hi, tmp);
    int i = lo, j = mid, k = lo;
    while (i < mid && j < hi) tmp[k++] = (a[i] <= a[j]) ? a[i++] : a[j++];  // <= keeps it stable
    while (i < mid) tmp[k++] = a[i++];
    while (j < hi) tmp[k++] = a[j++];
    for (k = lo; k < hi; k++) a[k] = tmp[k];
}
// call: mergeSort(a, 0, a.length, new int[a.length]);
function mergeSort(a) {
    if (a.length < 2) return a;
    const mid = a.length >> 1;
    const left = mergeSort(a.slice(0, mid)), right = mergeSort(a.slice(mid));
    const out = [];
    let i = 0, j = 0;
    while (i < left.length && j < right.length)
        out.push(left[i] <= right[j] ? left[i++] : right[j++]);   // <= keeps it stable
    while (i < left.length) out.push(left[i++]);
    while (j < right.length) out.push(right[j++]);
    return out;
}

Quick sort

Pick a pivot, partition so smaller values go left and larger go right, recurse on both sides. Fastest in practice; a random pivot makes the O(n²) worst case (e.g. already-sorted input) vanishingly unlikely.

void quickSort(vector<int>& a, int lo, int hi) {         // sorts [lo, hi]
    if (lo >= hi) return;
    swap(a[lo + rand() % (hi - lo + 1)], a[hi]);          // random pivot to the end
    int p = a[hi], i = lo;
    for (int j = lo; j < hi; j++)                          // Lomuto partition
        if (a[j] < p) swap(a[i++], a[j]);
    swap(a[i], a[hi]);                                     // pivot to its final spot
    quickSort(a, lo, i - 1);
    quickSort(a, i + 1, hi);
}
void quickSort(int[] a, int lo, int hi) {                   // sorts [lo, hi]
    if (lo >= hi) return;
    swap(a, lo + (int) (Math.random() * (hi - lo + 1)), hi); // random pivot to the end
    int p = a[hi], i = lo;
    for (int j = lo; j < hi; j++)                            // Lomuto partition
        if (a[j] < p) swap(a, i++, j);
    swap(a, i, hi);                                          // pivot to its final spot
    quickSort(a, lo, i - 1);
    quickSort(a, i + 1, hi);
}
void swap(int[] a, int i, int j) { int t = a[i]; a[i] = a[j]; a[j] = t; }
function quickSort(a, lo = 0, hi = a.length - 1) {          // sorts [lo, hi]
    if (lo >= hi) return;
    const r = lo + Math.floor(Math.random() * (hi - lo + 1));
    [a[r], a[hi]] = [a[hi], a[r]];                           // random pivot to the end
    const p = a[hi];
    let i = lo;
    for (let j = lo; j < hi; j++)                            // Lomuto partition
        if (a[j] < p) { [a[i], a[j]] = [a[j], a[i]]; i++; }
    [a[i], a[hi]] = [a[hi], a[i]];                           // pivot to its final spot
    quickSort(a, lo, i - 1);
    quickSort(a, i + 1, hi);
}

Heap sort

Turn the array into a max-heap, then repeatedly swap the max to the end and repair the heap. Guaranteed O(n log n) and in place — but not stable.

void siftDown(vector<int>& a, int i, int n) {
    while (2 * i + 1 < n) {
        int c = 2 * i + 1;                                  // left child
        if (c + 1 < n && a[c + 1] > a[c]) c++;              // bigger child
        if (a[i] >= a[c]) break;
        swap(a[i], a[c]); i = c;
    }
}
void heapSort(vector<int>& a) {
    int n = a.size();
    for (int i = n / 2 - 1; i >= 0; i--) siftDown(a, i, n);   // build heap: O(n)
    for (int end = n - 1; end > 0; end--) {
        swap(a[0], a[end]);                                 // max to the end
        siftDown(a, 0, end);
    }
}
void siftDown(int[] a, int i, int n) {
    while (2 * i + 1 < n) {
        int c = 2 * i + 1;                                  // left child
        if (c + 1 < n && a[c + 1] > a[c]) c++;              // bigger child
        if (a[i] >= a[c]) break;
        int t = a[i]; a[i] = a[c]; a[c] = t; i = c;
    }
}
void heapSort(int[] a) {
    int n = a.length;
    for (int i = n / 2 - 1; i >= 0; i--) siftDown(a, i, n);   // build heap: O(n)
    for (int end = n - 1; end > 0; end--) {
        int t = a[0]; a[0] = a[end]; a[end] = t;            // max to the end
        siftDown(a, 0, end);
    }
}
function siftDown(a, i, n) {
    while (2 * i + 1 < n) {
        let c = 2 * i + 1;                                  // left child
        if (c + 1 < n && a[c + 1] > a[c]) c++;              // bigger child
        if (a[i] >= a[c]) break;
        [a[i], a[c]] = [a[c], a[i]]; i = c;
    }
}
function heapSort(a) {
    const n = a.length;
    for (let i = (n >> 1) - 1; i >= 0; i--) siftDown(a, i, n);   // build heap: O(n)
    for (let end = n - 1; end > 0; end--) {
        [a[0], a[end]] = [a[end], a[0]];                    // max to the end
        siftDown(a, 0, end);
    }
}

Counting sort

For small integer ranges: count how many times each value appears, then write them back in order. No comparisons at all — O(n + k) for values in [0, k).

void countingSort(vector<int>& a, int k) {        // values in [0, k)
    vector<int> cnt(k, 0);
    for (int x : a) cnt[x]++;
    int i = 0;
    for (int v = 0; v < k; v++)
        while (cnt[v]--) a[i++] = v;
}
void countingSort(int[] a, int k) {               // values in [0, k)
    int[] cnt = new int[k];
    for (int x : a) cnt[x]++;
    int i = 0;
    for (int v = 0; v < k; v++)
        while (cnt[v]-- > 0) a[i++] = v;
}
function countingSort(a, k) {                     // values in [0, k)
    const cnt = new Array(k).fill(0);
    for (const x of a) cnt[x]++;
    let i = 0;
    for (let v = 0; v < k; v++)
        while (cnt[v]-- > 0) a[i++] = v;
}

Radix sort applies a stable counting sort digit by digit (least significant first) — O(d·(n + 10)) for d-digit numbers.

04 Built-in sorts & comparators

In interviews you’ll almost always call the library sort. Know its guarantees and how to write a comparator.

Sorting numbers

#include <algorithm>
vector<int> a = {5, 1, 4};
sort(a.begin(), a.end());                    // ascending, introsort, NOT stable
sort(a.begin(), a.end(), greater<int>());    // descending
stable_sort(a.begin(), a.end());             // stable (merge sort)
int arr[] = {3, 2, 1};
sort(arr, arr + 3);                          // plain arrays too
import java.util.*;
int[] a = {5, 1, 4};
Arrays.sort(a);                              // primitives: dual-pivot quicksort
Integer[] b = {5, 1, 4};
Arrays.sort(b, Collections.reverseOrder());  // descending needs boxed Integer[]
List<Integer> list = new ArrayList<>(List.of(5, 1, 4));
Collections.sort(list);                      // objects: TimSort, stable
const a = [10, 9, 1, 100];
a.sort();                    // ⚠ [1, 10, 100, 9] — compares as STRINGS!
a.sort((x, y) => x - y);     // ✔ ascending numbers
a.sort((x, y) => y - x);     // ✔ descending
const sorted = a.toSorted((x, y) => x - y);   // ES2023: returns a copy
// Array.prototype.sort is stable (guaranteed since ES2019)

Custom comparators & multiple keys

Sort people by age ascending, then by name for equal ages.

struct Person { string name; int age; };
sort(people.begin(), people.end(), [](const Person& a, const Person& b) {
    if (a.age != b.age) return a.age < b.age;    // must be a strict "less than"
    return a.name < b.name;
});
// or: tie(a.age, a.name) < tie(b.age, b.name)
record Person(String name, int age) {}
people.sort(Comparator.comparingInt(Person::age)
                      .thenComparing(Person::name));
// by hand: (a, b) -> a.age() != b.age() ? Integer.compare(a.age(), b.age())
//                                       : a.name().compareTo(b.name())
people.sort((a, b) =>
    a.age - b.age ||                     // numbers: subtract
    a.name.localeCompare(b.name)         // strings: localeCompare
);
// comparator returns < 0 (a first), 0 (keep order), > 0 (b first)
Comparator rules: it must be consistent — if a < b and b < c then a < c, and never “a < a”. In C++ returning <= instead of < is undefined behaviour and can crash std::sort. In Java, prefer Integer.compare(a, b) over a - b, which can overflow.

05 Sorting patterns in problems

👉👈

Sort + two pointers

Sorting unlocks pair/triplet search from both ends: two-sum on sorted data, 3Sum, boats, closest pair. O(n log n) total.

📅

Sort by a key, then sweep

Intervals by start or end, events by time, people by height. After sorting, one linear pass usually finishes the job.

🎯

Quickselect for k-th

Need only the k-th smallest/largest? Partition like quick sort but recurse into one side: average O(n).

🪣

Counting / bucket sort

Small value range or frequencies (top-k frequent, sort colors, max gap) → count instead of compare: O(n).

🔀

Merge sort + counting

Inversions, reverse pairs, “smaller numbers after self”: count cross pairs while merging two sorted halves.

🧩

Custom order

Largest number, relative sort, sort by frequency: the trick is entirely in the comparator.

06 Tips & tricks to learn it properly

🃏

Act them out

Sort 8 playing cards by hand with each algorithm. Insertion and selection become obvious in two minutes.

📏

Learn by invariant

Insertion: “prefix is sorted”. Selection: “prefix holds the smallest i items”. Quick: “left < pivot ≤ right”.

✍️

Write merge & partition from memory

They’re the two building blocks behind half of all sorting interview questions.

⚖️

Stability matters for multi-key

Sort by secondary key first, then stable-sort by primary key — or just use a two-key comparator.

🎲

Randomise the pivot

A fixed first/last pivot is O(n²) on sorted input — the most common real-world input!

🐣

Small n? Insertion sort

For n ≤ ~16 it beats everything; that’s why library sorts switch to it for tiny subarrays.

⚠️

JS: always pass a comparator

[10, 9, 1].sort() gives [1, 10, 9]. For numbers use (a, b) => a - b.

🧮

Do you even need to sort?

Top-k → heap or quickselect. Duplicates → hash set. Min/max → one pass. Sorting is O(n log n); these are O(n).

📦

Sort indices, not data

When you need original positions later, sort an index array by a[i] instead of moving values.

🧪

Test the nasty inputs

Empty, one element, all equal, already sorted, reversed, and duplicates. They break naive quick sorts.

🔢

Count the operations

Use the “Compare all” button above: see why O(n²) vs O(n log n) matters even at n = 60.

🗣️

Name the trade-off

Merge: stable, O(n) memory. Quick: fastest, worst case O(n²). Heap: guaranteed, not stable. Interviewers love this.

Common mistakes checklist

  • JavaScript sort() without a comparator on numbers.
  • Comparator that isn’t a strict ordering (<= in C++).
  • a - b comparator overflowing in Java with large values.
  • Quick sort with a fixed pivot on sorted / all-equal input.
  • Merge with < instead of <= → loses stability.
  • Off-by-one between [lo, hi] and [lo, hi) ranges in recursion.
  • Sorting when a hash set, heap or single pass would do.
